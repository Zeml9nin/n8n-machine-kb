Schedule Trigger Fires at the Wrong Hour

Published
2026-11-02
Checked against
docs.n8n.io
Status
Original

A weekly report that arrives on Friday evening for the wrong reason.

01Symptom and Cause

  • Symptom: A cron-style flow runs one or two hours off after a server move or a Docker rebuild.
  • Why: The trigger uses the workflow timezone, which falls back to the instance default.

02The Fix

  • Set the timezone in Workflow Settings for each time-sensitive flow.
  • On self-hosting set GENERIC_TIMEZONE and TZ in your container environment.
  • Remember that only activated workflows run on schedule.
