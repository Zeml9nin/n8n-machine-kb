Safe Retries for Money-Adjacent Flows

2026-11-02 · digest

Retries fix flaky APIs, but only if repeating a step cannot do harm.

1. Retry Without Duplicates
• Problem: A retried step charges, emails or inserts twice.
• Fix: Send a stable idempotency key and check for an existing record before writing.

2. Node Settings That Help
• Enable Retry On Fail and set Max Tries plus Wait Between Tries for rate-limited APIs.
• Use On Error > Continue (using error output) to route failures to a log branch.
• Keep each risky step in a small sub-workflow so a failure is easy to replay.
