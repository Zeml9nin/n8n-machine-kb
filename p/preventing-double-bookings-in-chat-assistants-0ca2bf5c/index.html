Preventing Double Bookings in Chat Assistants

Published
2026-11-02
Checked against
docs.n8n.io
Status
Original

Two customers pick the same slot within seconds and both get a confirmation.

01The Race

  • Problem: The flow checks free slots, then books later, and another run books in between.
  • Why: n8n does not lock external resources for you.

02The Fix

  • Check availability again immediately before the write, in the same step.
  • Store bookings in a database with a unique constraint on slot and resource.
  • On a constraint error answer with the next free slots instead of failing.
  • Limit parallel runs of the booking workflow if you cannot use a constraint.
